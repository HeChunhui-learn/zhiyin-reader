## 4.3 数据模型设计

### 4.3.1知音漫卷系统数据设计类图

为了持久保存知音漫卷系统中的用户信息、阅读进度和文档元数据，设计以下九张数据库表：

（1）用户表"T_User"：记录用户的账号、密码、昵称等信息，字段包括user_id（主键，VARCHAR）、account（VARCHAR，唯一）、password_hash（VARCHAR，加盐哈希存储，不保存明文）、salt（VARCHAR，密码盐值）、nickname（VARCHAR）、fail_count（INT，连续失败登录次数）、locked_until（TIMESTAMP，可空，锁定截止时间）、created_at（TIMESTAMP）、last_login（TIMESTAMP）。

（2）阅读进度表"T_ReadingProgress"：记录用户在各文档中的阅读位置与朗读进度，字段包括progress_id（主键，VARCHAR）、user_id（外键→T_User）、doc_id（VARCHAR）、device_id（VARCHAR）、chapter_index（INT）、paragraph_index（INT）、scroll_offset（FLOAT）、last_sentence_index（INT）、updated_at（TIMESTAMP）、version（INT，用于条件更新与增量同步）。朗读高亮位置为本机瞬态状态，不落库、不参与跨端同步。

（3）文档表“T_Document”：记录导入文档的元信息，字段包括 doc_id（主键，VARCHAR）、owner_id（外键→T_User）、file_name（VARCHAR）、file_format（VARCHAR，EPUB/TXT/MD）、file_size（BIGINT）、title（VARCHAR）、author（VARCHAR）、content_hash（VARCHAR，用于重复导入去重）、resource_url（VARCHAR）、imported_at（TIMESTAMP）。

（4）段落表“T_Paragraph”：记录文档的段落顺序与文本，字段包括 para_id（主键，VARCHAR）、doc_id（外键→T_Document）、para_index（INT）、text（TEXT）。

（5）句子表“T_Sentence”：记录逐句跟读所需的句子边界，字段包括 sentence_id（主键，VARCHAR）、para_id（外键→T_Paragraph）、sentence_index（INT）、start_offset（INT）、end_offset（INT）。

（6）图片资源表“T_ImageResource”：记录图文混排中的图片引用与本地缓存键，字段包括 image_id（主键，VARCHAR）、doc_id（外键→T_Document）、para_index（INT）、src（VARCHAR）、cache_key（VARCHAR）、local_url（VARCHAR）、remote_url（VARCHAR）。

（7）同步记录表“T_SyncRecord”：记录跨设备同步的版本与冲突信息，字段包括 record_id（主键，VARCHAR）、user_id（外键→T_User）、doc_id（外键→T_Document）、device_id（VARCHAR）、state（VARCHAR）、local_delta（TEXT，JSON）、remote_changes（TEXT，JSON）、conflict_json（TEXT，JSON）、version（INT）、updated_at（TIMESTAMP）。

（8）书签表“T_Bookmark”：记录读者在各文档中收藏的位置，字段包括 bookmark_id（主键，VARCHAR，由客户端生成的唯一标识）、user_id（外键→T_User）、doc_id（外键→T_Document）、anchor_json（TEXT，位置锚点的 JSON 表示）、name（VARCHAR，书签名称）、version（INT，用于条件更新）、created_at（TIMESTAMP）、updated_at（TIMESTAMP）、deleted_at（TIMESTAMP，可空，软删除墓碑，非空表示已删除）。书签标识由客户端生成，使两端各自新增的书签天然具有不同主键，从而可并集合并；deleted_at 采用软删除，使其他设备在增量拉取时能够获知删除事件。

（9）令牌表“T_Token”：记录刷新令牌的签发与轮换，字段包括 token_id（主键，VARCHAR）、user_id（外键→T_User）、device_id（VARCHAR）、refresh_hash（VARCHAR，刷新令牌的哈希值，不保存明文令牌）、expires_at（TIMESTAMP）、created_at（TIMESTAMP）、revoked_at（TIMESTAMP，可空）。访问令牌不落库，其有效性由签名与服务端密钥校验。

### 4.3.2 知音漫卷系统数据的操作设计

为了支持对上述数据库表的操作，设计模型中有一个关键设计类”DataAccessLibrary”，它提供了一组方法以实现将数据层对象的数据插入到对应数据表中、或者从中删除、或者修改表中的数据、或者从数据库表中查询相关的信息等等。该类以仓储（Repository）的形式组织，对上层隐藏具体的存储介质与存取细节，其具体的接口描述如下。

void openDatabase()

void closeDatabase()

boolean insertUser(User)

boolean deleteUser(User)

boolean updateUser(User)

User getUserByAccount(account)

boolean verifyUserValidity(account, password)

boolean insertDocument(Document)

boolean deleteDocument(docId)   // 级联删除该文档的段落、句子、图片引用、书签与各设备阅读进度

Document getDocumentById(docId)

List&lt;Document&gt; listDocumentsByUser(userId)

Document getOwnDocumentByHash(ownerId, contentHash)

boolean insertParagraph(Paragraph)

List&lt;Paragraph&gt; listParagraphsByDocument(docId)

boolean insertSentence(Sentence)

List&lt;Sentence&gt; listSentencesByParagraph(paraId)

boolean insertImageResource(ImageResource)

boolean updateImageResource(ImageResource)

boolean insertReadingProgress(ReadingProgress)

ReadingProgress getProgressByDocAndDevice(docId, deviceId)

int countBookmarksByDocument(userId, docId)

boolean deleteParagraphsByDocument(docId)

boolean deleteSentencesByDocument(docId)

boolean deleteImageResourcesByDocument(docId)

boolean deleteReadingProgressByDocument(userId, docId)

DataAccessLibrary()

其中，verifyUserValidity 封装了从 T_User 表读取记录并完成加盐哈希比对的完整过程，供”用户注册与登录”用例调用；updateAnchor 在更新位置锚点的同时递增 version 字段，供”跨设备进度同步”用例在合并后调用；enqueuePendingChange 与 flushPendingChanges 成对使用，实现离线变更的本地排队与联网后的批量补报，供”同步冲突处理”用例在网络中断时降级使用。所有写操作均在事务中执行，任一步骤失败时回滚，以保证进度与冲突记录的一致性。
