## 2.1 软件需求的用例模型

图 2-1 给出了知音漫卷系统的用例模型。系统边界内的用例共 11 个，与第 1.2 节所述功能相对应，按业务主题可分为账号管理、内容接入、阅读增强与数据同步四组：

### 2.2.1 用例名：用户注册与登录

2.2.1.1 用户注册与登录用例描述

用例名：用户注册与登录

业务目标：读者通过注册获得个人账号，并通过登录获得令牌与阅读权限，进入阅读器主界面。

执行者：

主动执行者：读者

被动执行者：云端存储服务（为系统提供账号数据的持久化）

前置条件：读者已打开系统首页，网络连接可用。

触发条件：读者在未登录状态下发起“登录／注册”。

基本交互动作：

1. 读者在登录界面输入账号与密码，提交登录请求。

2. 登录视图将账号与密码传递给认证控制器。

3. 服务端读取该账号的用户记录，其中包含盐值与密码摘要。

4. 认证控制器在服务端调用用户实体，以盐值与密码摘要完成加盐哈希比对。

5. 校验通过后，认证控制器以服务端密钥签发访问令牌与刷新令牌并缓存会话；密码摘要与签名密钥均不出服务端，前端只保存令牌。

6. 认证控制器将用户信息与令牌返回登录视图，登录视图切换至阅读器主界面。

步骤 1～6 顺序执行，登录成功后结束。

扩展交互动作：

3a. 云端存储服务返回“账号不存在”

3a1 认证控制器返回错误信息，登录视图提示账号不存在，并引导读者转入注册流程。

4a. 密码校验不通过

4a1 认证控制器返回认证失败，登录视图提示密码错误，交互动作回到动作 1 重新输入。

6a. 令牌签发失败或网络中断

6a1 认证控制器记录失败原因，登录视图提示“登录失败，请稍后重试”，并保留读者已输入的内容。

后置条件：读者已获得有效令牌，会话状态建立，进入阅读器主界面；若登录未成功，系统停留在登录界面，读者已输入的内容保留。

非功能需求：

1. 性能：登录请求在正常网络条件下响应时间不超过 460ms。

2. 可靠性：认证服务不可用时应给出明确错误提示且不丢失读者已输入的内容；本地已缓存的登录态在离线状态下允许进入离线阅读模式。

3. 业务规则：账号在系统内唯一，密码以加盐哈希方式存储，不保存明文；登录成功后签发的 JWT 令牌具有有效期，过期需通过刷新令牌重新获取；同一账号的失败登录次数达到阈值后触发短时锁定。

### 2.2.2 用例名：导入并解析文档

2.2.2.1 导入并解析文档用例描述

用例名：导入并解析文档

业务目标：读者将本地 EPUB、TXT 或 Markdown 文档导入系统，系统将其解析为结构化数据并加入书架。

执行者：

主动执行者：读者

被动执行者：对象存储／CDN（为系统托管原始文件与提取出的图片资源）

前置条件：读者已登录；所选文件格式受支持且未损坏。

触发条件：读者在书架界面发起“导入文档”并选定本地文件。

基本交互动作：

1. 读者在书架界面选择本地文件（EPUB／TXT／Markdown）。

2. 书架视图将文件与格式信息交由文档解析器解析。

3. 文档解析器按格式选择对应的解析器，并正则匹配文本中的图片引用标记。

4. 文档解析器创建文档实体，写入元数据、段落与图片引用信息。

5. 文档解析器将原始文件上传至服务端（由服务端转存至对象存储／CDN）并获取资源 URL；图片资源不在导入阶段上传，改由读者首次浏览到该图片时按需上传。

6. 文档解析器将文档元数据与解析结果返回书架视图，文档入书架并提示解析完成。

扩展交互动作：

3a. 文件格式不受支持

3a1 文档解析器返回“格式不支持”错误，书架视图提示读者并终止流程。

3b. 文件损坏或解析失败

3b1 文档解析器捕获异常并返回失败原因，书架视图提示“文档解析失败”，文档不加入书架。

5a. 资源上传失败

5a1 文档解析器保留本地解析结果，并将文档标记为“仅本地可见”，待网络恢复后重试上传。

后置条件：文档完成解析并加入书架，结构化内容可供渲染与跟读模块使用。

非功能需求：

1. 性能：10MB 以内的文档在正常网络条件下解析与入库时间不超过 3s。

2. 可靠性：解析失败不得导致应用崩溃，且已解析的其他文档不受影响。

3. 业务规则：单个文档的解析结果需保留段落顺序与图片引用的上下文位置；同一文档重复导入时应以内容哈希去重，避免产生重复条目；解析过程不得修改用户的原始文件。

### 2.2.3 用例名：图文混排阅读

2.2.3.1 图文混排阅读用例描述

用例名：图文混排阅读

业务目标：读者打开文档进行滚动阅读，系统在文字对应位置内联呈现插图，并保证长文档滚动流畅。

执行者：

主动执行者：读者

被动执行者：对象存储／CDN（为系统提供图片资源）

前置条件：文档已完成解析；读者处于阅读界面。

触发条件：读者在书架中打开某文档。

基本交互动作：

1. 读者打开文档并滚动阅读。

2. 阅读器视图请求渲染控制器渲染文档。

3. 渲染控制器依据结构化数据构建段落与图片占位容器的 DOM。

4. 当图片占位容器进入视口时，阅读器视图触发加载（IntersectionObserver 回调）。

5. 渲染控制器查询图片缓存，命中则直接读取本地 Blob。

6. 未命中时渲染控制器向服务端资源接口请求图片资源（由服务端内部再向对象存储／CDN 取回），并将返回的 Blob 写入图片缓存。

7. 渲染控制器将图片内联显示在对应位置并移除骨架占位。

步骤 4～7 在滚动过程中循环执行，直至文档阅读完毕。

扩展交互动作：

3a. 读者快速滚动使占位元素离开视口

3a1 取消尚未发起的加载请求；已加载但不可见的图层按策略回收内存。

6a. 图片请求失败或超时

6a1 渲染控制器展示加载失败占位并提供重试入口，不阻塞正文阅读。

后置条件：图文混排内容完整呈现，图片资源进入本地缓存，供二次访问直接命中。

非功能需求：

1. 性能：已缓存图片的显示响应不超过 100ms；未缓存图片在正常网络条件下不超过 460ms。

2. 可靠性：单张图片加载失败不得影响正文与其他图片的渲染；长时间滚动不应造成内存持续增长。

3. 业务规则：图片未进入视口时不得发起网络请求；图片应与正文段落顺序保持一致，不破坏文字与插图的对应关系；缓存容量达到上限时按最近最少使用（LRU）策略淘汰。

### 2.2.4 用例名：逐句高亮跟读

2.2.4.1 逐句高亮跟读用例描述

用例名：逐句高亮跟读

业务目标：读者开启跟读后，系统按句子粒度朗读正文，当前朗读句子在正文中实时高亮，并自动滚动跟随。

执行者：

主动执行者：读者

被动执行者：TTS 语音合成服务（为系统提供逐句语音合成能力）

前置条件：文档已完成解析且包含可朗读正文；TTS 服务可用。

触发条件：读者在阅读界面选定音色与语速后发起“逐句跟读”。

基本交互动作：

1. 读者选择音色与语速，发起“逐句跟读”。

2. 阅读器视图将句子列表、音色与语速传递给跟读控制器。

3. 跟读控制器按中文标点与边界规则将正文切分为句子列表。

4. 跟读控制器请求 TTS 服务合成第 i 句音频，并接收返回的音频片段。

5. 跟读控制器建立“句子→音频片段”映射，写入音频片段实体并缓存。

6. 跟读控制器驱动阅读器视图播放音频并高亮第 i 句，容器自动滚动至高亮位置。

7. 第 i 句播放结束（onended 事件）后，跟读控制器将游标推进至 i+1，回到动作 4。

步骤 4～7 循环执行，直至全文句子朗读完毕或读者主动停止。

扩展交互动作：

4a. 首句合成与播放之间存在等待

4a1 跟读控制器预先合成后续句子（预加载），减少句间停顿。

4b. TTS 服务不可用或合成失败

4b1 降级为浏览器原生 SpeechSynthesis 接口。

6a. 读者在高亮推进过程中手动回翻或跳读

6a1 暂停自动滚动，保留当前高亮位置；读者可发起“继续跟读”平滑接管。

后置条件：正文按句朗读完毕或读者主动停止；朗读进度与高亮位置一致，可直接用于进度记录。

非功能需求：

1. 性能：句间切换的高亮推进延迟不超过 100ms；预加载缓冲不少于 2 句。

2. 可靠性：单句合成失败不应中断整体跟读流程，应跳过该句并继续；跟读过程中切换前后台或息屏时，应保存当前句子索引以便恢复。

3. 业务规则：高亮必须以句子为最小粒度，且与当前播放的音频片段严格对应；用户手动操作（暂停、跳转、调速）的优先级高于自动推进；朗读过程中不得修改文档内容。

### 2.2.5 用例名：跨设备进度同步

2.2.5.1 跨设备进度同步用例描述

用例名：跨设备进度同步

业务目标：读者在另一台设备打开同一文档时，系统自动恢复其上次的阅读位置，实现无缝续读。

执行者：

主动执行者：读者

被动执行者：云端存储服务（保存并读取进度数据）

前置条件：读者已登录且设备具有唯一设备标识；该文档存在云端或本地进度记录。

触发条件：读者在新设备登录并打开此前阅读过的文档。

基本交互动作：

1. 读者在新设备打开同一文档。

2. 阅读器视图调用同步控制器发起同步，传入文档标识与设备标识。

3. 同步控制器向云端存储服务拉取该用户在该文档上的全部设备进度记录与版本号。

4. 同步控制器读取本地进度记录。

5. 同步控制器比对双方时间戳，以最新者为准合并，并识别是否需要恢复。

6. 同步控制器更新阅读进度实体的章节、段落与滚动偏移量。

7. 同步控制器请求阅读器视图按锚点定位，页面滚动至上次阅读位置。

扩展交互动作：

5a. 云端无记录

5a1 以本地进度为准，并将本地进度首次上报至云端。

5b. 双方记录均存在且版本号不一致

5b1 转入“同步冲突处理”用例，按裁决结果恢复阅读位置。

7a. 锚点定位失败（文档已变更或段落缺失）

7a1 降级为按章节起始位置定位，并提示读者。

后置条件：本地与云端的阅读进度一致，读者在新设备上恢复至上次阅读位置。

非功能需求：

1. 性能：进度同步请求在正常网络条件下响应时间不超过 460ms。

2. 可靠性：网络不可用时应以本地进度继续阅读，并将待同步变更写入本地队列，联网后自动补报。

3. 业务规则：跨端同步的数据对象为阅读进度锚点与书签集合。书签按唯一标识并集合并，同一书签的并发修改两份均保留、不静默丢弃；阅读进度取较新者并施加不回退保护（较新记录的位置早于本地已读位置时保留较前的位置），被舍弃的一份写入冲突记录供读者查看。每台设备具有唯一设备标识，同一设备的重复同步请求应被识别并忽略；同步采用增量方式，仅上传与拉取发生变更的数据。朗读高亮位置为本地瞬态状态，不参与同步。

### 2.2.6 用例名：同步冲突处理

2.2.6.1 同步冲突处理用例描述

用例名：同步冲突处理

业务目标：当同一文档在不同设备上被并发修改且无法自动合并时，向读者展示冲突内容并由读者决定保留方案，完成一致性收敛。

执行者：

主动执行者：读者

被动执行者：云端存储服务（校验版本号并持久化合并结果）

前置条件：读者已登录；同一文档存在两台及以上设备的未同步变更。

触发条件：提交本地变更时检测到云端版本号与本地基准版本不一致。

基本交互动作：

1. 同步控制器向云端存储服务提交本地增量变更（携带基准版本号）。

2. 云端存储服务检测到版本不一致，返回冲突响应。

3. 同步控制器读取双方的变更记录集。

4. 同步控制器逐段比对，判定是否可自动合并。

5. 无法自动合并时，同步控制器将冲突列表与差异内容返回阅读器视图，界面展示冲突项。

6. 读者选择或合并要保留的变更项。

7. 同步控制器将合并结果提交至云端存储服务，生成新版本号，同步状态更新为“已同步”。

扩展交互动作：

4a. 两端修改互不影响、可自动合并

4a1 直接合并并将结果提交云端，不打扰读者。

6a. 读者暂不处理冲突

6a1 保留冲突状态，界面持续显示冲突标识，允许稍后处理。

7a. 提交失败（网络中断）

7a1 保留本地合并结果并进入待同步队列，联网后重试。

后置条件：冲突已消解，本地与云端数据一致，文档版本号更新。

非功能需求：

1. 性能：冲突检测在提交请求中同步完成，不额外增加超过 200ms 的时延。

2. 可靠性：冲突处理中断（如关闭页面）后，未决冲突记录不得丢失，下次进入时应可继续处理。

3. 业务规则：冲突判定以版本号为准，不以时间戳单独判定；书签冲突按"同时保留"处理——同一书签并发重命名时两份均保留，删除与修改冲突时保留修改后的书签；任何自动合并都必须保证不丢失用户的任一变更，无法保证时必须交由用户决策；冲突处理过程不得阻塞读者的正常阅读，未处理的冲突不阻止继续阅读。

# 3.1 性能要求

1）功能响应时间要求：网络连接建立后，服务端应能稳定响应用户发送的请求。界面交互类操作（翻页、高亮推进、播放控制等）响应时间不超过 100ms；涉及网络的轻量操作（登录认证、进度同步等）在正常网络条件下响应时间不超过 460ms；文档解析与入库的指标见本条 4）与表3-1。

2）语音合成与跟读延迟要求：逐句跟读时，句间高亮推进延迟不超过 100ms；引擎应至少预加载 2 句音频，避免可感知的句间停顿；在预加载缓冲命中的条件下，音频起播延迟不超过 120ms（首次合成不计入本口径），朗读流畅、无卡顿、无花屏。

3）图片加载要求：已缓存图片的呈现响应不超过 100ms；未缓存图片在正常网络条件下不超过 460ms；长文档滚动过程中不应出现明显掉帧或白屏。

4）容量与运行要求：单文档支持不少于 2000 个段落与 500 张插图；系统支持 7×24 小时长期稳定运行，服务端最低配置为普通 Windows 笔记本（4 核 8GB 及以上）即可支撑原型系统，且系统维护不应影响阅读功能的正常使用。

5）资源占用要求：阅读界面在长文档（不少于 500 段落）连续滚动 30 分钟后，须满足：①页面 DOM 节点总数不超过当前渲染窗口上限（视口窗口量的 3 倍以内）；②JavaScript 堆占用首尾采样值之差不超过 10%；③DOM 节点数与堆占用不随阅读时长呈线性增长。浏览器垃圾回收为非确定性行为，堆占用必然呈锯齿波动，故以趋势与上限作为判定口径，并依靠不可见图层的回收机制达标。

| 指标项 | 要求 | 说明 |
| 界面交互响应时间 | 不超过 100ms | 翻页、高亮推进、播放控制等本地操作 |
| 网络请求响应时间 | 不超过 460ms | 登录认证、进度同步等轻量请求 |
| 文档解析与入库 | 不超过 3s | 10MB 以内文档（含结构化入库） |
