## 1. 句子切分边界规则

### 1.1 规则表

规则以段落为第一层边界（句子不跨段落），段落内按下表切分。切分结果写入 `T_Sentence`，与 `sentence_index` 一一对应，索引自 0 起连续编号。

| 序号 | 规则 | 说明 |
|---|---|---|
| R1 | 句末标点切分 | `。`、`！`、`？`、`…` 及其组合（`？！`、`！？`、`……`）视为句末边界；标点**归属前一句**，不单独成句 |
| R2 | 分号与冒号不切分 | `；`、`：` 仅作句内停顿，不产生新句 |
| R3 | 引号与括号内的句末标点同样切分 | 但配对收尾符号（`”`、`）`、`』`）归属前一句，**下一句不得以收尾符号开头** |
| R4 | 连续省略号只算一次边界 | `……` 与 `．．．．．．` 均按一个句末边界处理，不产生空句 |
| R5 | 缩写与小数不切分 | 形如 `3.14`（句点两侧均为数字）与 `Mr.`/`No.` 等缩写白名单中的句点不作边界 |
| R6 | 段落内换行按句内空白处理 | 换行、制表符、连续空格在切分前归一为单个空格 |
| R7 | 切分前先归一化 | 剔除段落首尾空白与零宽字符；`start_offset`/`end_offset` 以归一化后的段落文本为准 |
| R8 | 超长句兜底 | 单句长度超过 **200 字**时，在最近的 `，`/`、` 处强制切分；仍无标点则按 200 字硬切，以保证单句音频时长可控 |
| R9 | 空句不得入表 | 纯标点、纯空白或长度为零的片段一律丢弃 |
| R10 | 索引稳定性 | 句子索引在文档解析结果不变的前提下保持稳定；切分规则变更视为内容升级，须重新生成句子表与音频缓存 |

### 1.2 切分示例

| 输入段落 | 切分结果 | 适用规则 |
|---|---|---|
| 他说：“我不去。”然后走了。 | ①他说：“我不去。” ②然后走了。 | R1 + R3 |
| 等等……这是真的吗？ | ①等等…… ②这是真的吗？ | R1 + R4 |
| 圆周率约等于 3.14，不是 3.15。 | ①圆周率约等于 3.14，不是 3.15。 | R5（小数不切） |
| 他抬头；天上没有星星，只有雾。 | ①他抬头；天上没有星星，只有雾。 | R2（分号不切） |
| （无句末标点、超过 200 字的长段落） | 按 R8 在最近的逗号处强制切分 | R8 |

### 1.3 与既有内容的关系

1. 需求规格说明书 1.3.1 节与 2.2.4 节的"按中文标点与边界规则切分"，其规则内容即以本文档 1.1 节为准。
2. 边界规则属于算法实现细节，建议在设计规格说明书 **4.1.4 节**「逐句高亮跟读」用例设计方案的末尾以表格形式插入（表4-X 句子切分边界规则），并在其正文中把"基于中文标点（。！？；等）与边界规则"改为"按表4-X 所列边界规则"，使正文与规则表互相指引。
3. 需求规格说明书侧**不必改动**：需求文档只描述"按标点与边界规则切分"这一行为，规则细节属于设计阶段内容。

## 2. 阅读进度表 `highlight_sentences` 字段的语义

### 2.1 现状与冲突

设计规格说明书 4.3.1 节的阅读进度表 `T_ReadingProgress` 中设有 `highlight_sentences`（TEXT，JSON 数组）字段，需求规格说明书 1.2 节「跨设备进度同步」一行亦记载同步"书页位置、**高亮记录**与书签"。但两份文档中：

1. **没有任何用例、界面命令元素或数据操作接口能够创建该高亮**——阅读界面 `ReaderView` 的命令元素只有渲染、高亮句子、锚点定位与图片懒加载，没有"添加高亮标注"；用例模型中也没有对应用例。
2. 若该字段指**朗读高亮游标**（需求规格说明书 1.3.1 节即用此含义），则它是播放过程中的瞬态状态，位置完全由本机播放进度决定，**不应持久化同步**；把高频变化的播放位置纳入同步会引入本可避免的并发冲突。
3. 本项目已明确：跨端同步的两类数据对象仅为**阅读进度锚点**与**书签集合**，朗读高亮位置以本机定位为准。

因此该字段必须二选一：要么按朗读瞬态状态处理并从同步范围中剔除，要么升级为一项真实的用户标注功能。

### 2.2 三个处置方案

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 删除该字段（推荐）** | 从 `T_ReadingProgress` 删除 `highlight_sentences`，仅保留 `last_sentence_index`（用于本机恢复跟读位置）。同时删除需求规格说明书表3-3 书架侧边栏中的"我的高亮"导航项——该功能既无用例也无界面命令元素，属于无支撑的界面残留 | 改动最小，且使三处口径一致；无功能损失（读者仍可看到朗读高亮的实时显示） |
| B. 保留字段但限定为本机缓存 | 字段保留在 `T_ReadingProgress`，但明确标注"仅本机读写、不上报、不参与合并" | 字段存在但语义仍是瞬态状态，容易被后续实现误用为同步数据；文档需额外说明 |
| C. 升级为文本高亮标注功能 | 新增用例「文本高亮标注」（需求 11 → 12 个用例）、实体类与数据表、阅读界面的标注命令元素，并把高亮纳入同步范围 | 工作量显著增加（约 3–4 人日），且需重新绘制分析类图与设计类图；与本项目"不提供修改正文与标注能力"的既定范围不符 |

### 2.3 若选方案 A 需改动的位置

| 序号 | 文档与位置 | 修改内容 |
|---|---|---|
| 1 | 设计规格说明书 4.3.1 节（2）阅读进度表 | 删除 highlight_sentences 字段（已删除）；原字段说明改为"朗读高亮位置为本机瞬态状态，不落库、不参与同步" |
| 2 | 设计规格说明书 4.2 节 | `ReadingProgress` 的属性中不再出现高亮相关字段（现文档未列，无需改动） |
| 3 | 设计规格说明书 3.1.3 节书架界面（含表3-3） | 删除侧边栏导航项"我的高亮"（保留"我的书签"，该书签已有完整链路） |
| 4 | 需求规格说明书 1.2 节 表1-1 | 「跨设备进度同步」一行已在本轮改为"同步阅读进度锚点与书签集合"，无需再改 |
