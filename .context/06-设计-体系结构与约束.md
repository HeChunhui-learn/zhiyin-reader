# 第2章 软件体系结构设计

图2-1描述了”知音漫卷”系统的设计架构，采用分层体系结构，包括用户界面层（界面层）、业务逻辑层、数据层，以及与外部系统交互的接口层。其中：

界面层负责显示用户界面，承担了“GuidingUI”、“LoginView”、“LibraryView”、“ReaderView”、“PlaybackBar”、“ConflictDialog”与用户交互有关的职责。该层仅负责输入采集、状态呈现与界面切换，不包含业务规则。

业务逻辑层负责核心业务逻辑处理，它将承担”AuthController”、“DocumentParser”、“RenderController”、“ReadAlongController”、“SyncController”、“BookmarkController”的所有职责。该层是用例职责的承担者，负责分解任务、调度数据层与接口层，是分层之间唯一的协调者。

数据层负责系统的数据存储，它包括了”User”、“Document”、“Paragraph”、“Sentence”、“AudioClip”、“ImageResource”、“ReadingProgress”、“SyncRecord”、“Bookmark”。该层承载具有持久意义的信息项，并向业务逻辑层提供信息访问操作。

此外，系统需调用外部系统与外部设备，故设置接口层。该层由接口类构成，为业务逻辑层提供对外访问能力：“CloudStorageAPI”用于与”云端存储服务”交互，实现用户认证数据、阅读进度数据与书签数据的持久化读写；“ServerAPI”为前端提供图片资源的统一入口（前端不直接访问对象存储）；“LocalStoreAPI”封装浏览器端 IndexedDB 的图片与音频缓存读写；“ObjectStorageAPI”用于与”对象存储／CDN”交互，负责原始文档与图片资源的存取，由服务端内部调用；“TTSEngineAPI”用于与”TTS 语音合成服务”交互，负责将文本句子合成为音频流；“AIChatService”为后续”大模型 AI 伴读服务”预留，实现上下文感知的答疑能力；“DataAccessLibrary”为数据访问接口，是业务逻辑层访问数据层的唯一入口，逻辑上归属于数据层，在设计类图中与外部系统接口同列绘制。

系统各层的依赖方向单向向下：界面层依赖业务逻辑层，业务逻辑层依赖数据层，业务逻辑层横向依赖接口层；数据层不反向依赖任何上层，接口层不反向依赖业务逻辑层。这一约束保证了信息隐藏，使得替换外部服务或调整持久化机制时改动范围可控。

## 1.2 软件设计的约束和限制

-运行环境要求：现代浏览器（Chrome 80+、Firefox 80+、Edge 80+、Safari 14+）；服务端与语音合成推理服务运行于同一台普通 Windows 笔记本（Windows 10/11，4 核 8GB 及以上），同时兼容 Linux／macOS

-开发语言与框架：前端 TypeScript + React 18 + Vite；后端 Node.js 20 + TypeScript（Fastify 框架）；数据库 SQLite

-标准规范：ESLint + Prettier编码规范，RESTful API设计规范

-开发工具：VS Code、Git、Chrome DevTools

-部署与依赖约束：单机部署，不使用云服务器；语音合成默认使用本地自托管的 Kokoro-FastAPI，不依赖付费云服务；跨设备演示限同一局域网内，公网访问不在本期范围；所有第三方服务密钥仅存放于服务端。
