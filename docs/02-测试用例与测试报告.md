## 1. 测试范围与环境

### 1.1 被测对象

| 部件 | 说明 |
|---|---|
| 前端 | React 18 + Vite + TypeScript，`client/` |
| 服务端 | Node.js 20 + Fastify + SQLite，`server/` |
| 接口 | 遵循《接口说明文档》契约（`自主规划文档/接口说明文档-第1组2026.docx`） |

### 1.2 测试环境

| 项目 | 配置 |
|---|---|
| 操作系统 | Windows 11 |
| 运行时 | Node.js 24.20.0（要求 20+） |
| 数据库 | SQLite 单文件，每次用例前重建 |
| 浏览器环境 | 无头 DOM（jsdom）+ fake-indexeddb，模拟浏览器 API |
| 语音上游 | 本地模拟的 OpenAI 兼容 TTS 服务（三种模式：正常 / 不可用 / 超时） |

### 1.3 为什么用无头环境

五个模块里有三个（图片懒加载、跟读、同步）都依赖浏览器专有 API。用 jsdom 把
`IntersectionObserver`、`SpeechSynthesis`、`HTMLMediaElement`、`IndexedDB`
都补上替身之后，可以把整个界面**真实挂载**进 DOM 跑完整生命周期，
断言的是"界面上真的出现了什么"，而不是"函数返回了什么"。

这比只测纯函数更接近实际，也因此在开发过程中抓出了好几个只有真跑才会暴露的问题。

## 2. 测试方法

分四类：

| 类型 | 做法 | 覆盖 |
|---|---|---|
| **纯函数对拍** | 与 Node 的 `crypto` 对拍（SHA-256）、与手算结果对拍（切句、窗口几何） | 解析、切分、缓存键、几何计算 |
| **接口用例** | 直接打 HTTP，断言状态码、错误码、响应体结构、数据库副作用 | 认证、文档、图片、TTS 代理、同步 |
| **界面挂载用例** | 把 `App` 挂进 jsdom，模拟点击/输入/滚动，断言渲染出来的 DOM | 登录、导入、阅读、跟读、书签、冲突 |
| **回归** | 每轮开发结束后把此前所有用例重跑一遍 | 全部 |

**判定标准**：每条断言必须是二值的（通过 / 失败），不允许"看起来对"。界面类断言一律
检查真实 DOM 文本或节点。

## 5. 发现并修复的缺陷

**这一节是本报告最有价值的部分。** 下列缺陷全部是"只有真正跑起来才会暴露"的，
其中多条如果留到演示现场才发作，代价会很大。

| 编号 | 现象 | 根因 | 修复 | 验证用例 |
|---|---|---|---|---|
| **D-01** | Markdown 里的图片语法原样出现在正文中（阅读器把 `![封面](images/cover.jpg)` 当文字显示） | 图片段落文字为空时，解析器回退用了 token 的原始文本 | 纯图片段落记为 `img` 类型、文字留空；兜底路径也剥离图片语法 | PA-07 |
| **D-02** | 网络请求卡住时，界面永远停在"正在加载"，没有任何提示 | 请求没有超时 | 加 15 秒 AbortController，超时按网络错误处理并给中文提示 | 手工 |
| **D-03** | 演示账号登不进去，种子里的《人间词话》谁都看不到 | 种子脚本写了占位密码哈希 | 用与登录接口相同的 scrypt 生成真实哈希 | AU-04 |
| **D-04** | **每张图泄漏一个 object URL**（长文档读到后面内存持续上涨） | epub.js 在二进制模式下默认 `replacements: "blobUrl"`，会为每个资源创建一个由它自己持有、调用方拿不到的 object URL | 显式关掉：`{ replacements: 'none' }` | PA-14 |
| **D-05** | **EPUB 里的图一张都取不到** | epub.js 的 `Archive.getBlob` 内部是 `url.substr(1)`（写死了去掉第一个字符），只认带前导斜杠的路径；而路径拼接时把斜杠吃掉了 | 保留前导斜杠，并补了按文件名兜底匹配 | PA-11 |
| **D-06** | `<figure><img/><figcaption/></figure>` 里的图整张漏掉 | `querySelectorAll` 查不到元素自己，而 `img` 是被遍历到的那个子元素本身 | 加显式的 `IMG` 分支 | PA-12 |
| **D-07** | 阅读器把包内路径 `/OEBPS/images/fig1.png` 当图片说明文字显示 | 契约 §4.1 的 imageRefs 里有 `alt` 字段，但数据表没有对应列，导入时丢弃了 | 补 `T_ImageResource.alt` 列并贯通到前端 | IM-04 |
| **D-08** | **4 句的书显示"第 5 / 4 句"，高亮整个消失** | 念完最后一句后游标没有夹紧，越过了末尾 | `Math.min(i + 1, length - 1)` | RA-09 |
| **D-09** | 在无全局 `Audio` 构造函数的环境下播放器直接抛错 | 用了 `new Audio()` | 改用 `document.createElement('audio')` | RA-04 |
| **D-10** | 契约规定的 TTS 缓存键 `sha256(engine+voice+rate+text)` 直接拼接有歧义（`("a","b")` 与 `("ab","")` 同键） | 契约本身的缺陷 | 加 `\u0001` 分隔符，客户端与服务端同步 | TT-16 |
| **D-11** | **"两端改同一书签"根本不触发冲突**，同步静默跳过 | 契约 §8.1 的 `updated` / `deleted` 条目里**没有 `docId`**（只有 `created` 有），而实现要求每条都带 | 靠 `bookmarkId` 反查 docId | SY-17 |
| **D-12** | **一次"只改名"的同步会把书签位置冲成第 0 段** | 同上，`updated` 条目里也没有 `anchor`，`normalizeAnchor(undefined)` 返回全零 | 锚点缺省时沿用库里已有的 | SY-11 |
| **D-13** | 冲突提示一闪而过，且界面只有角标、没有任何文字说明 | `setError(冲突说明)` 之后紧跟的 `reload()` 成功又把它清空；且该错误压根没渲染 | 调整顺序；补上提示条与「查看冲突」按钮 | SY-32 |
| **D-14** | 滚动节流用了 `requestAnimationFrame`，后台标签页不触发，且无头环境没有它 | 实现选择不当 | 换成 16ms 的 `setTimeout` | SY-35 |
| **D-15** | 建库时无法区分标题段与正文段 | 04 §4.3.1 的 `T_Paragraph` 字段清单里没有 `para_type` | 补列（已在交付说明中记明，建议 04 同步补上） | PA-02 |

**另有 3 处是文档之间的矛盾，已按"契约优先"裁决并在《设计说明》中记录**：
锚点字段名（`paraIndex` → `paragraphIndex`）、`serverReceivedAt` 列缺失、
`postBeacon` 的用法（它只能发 POST 且不能设请求头，而接口是 PUT 且要带令牌，技术上走不通）。

### 6.1 未做的测试
