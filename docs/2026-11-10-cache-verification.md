# 阅读与语音缓存验证

日期：2026-11-10。按读者选择完善现有缓存，未引入 Redis 或新增依赖。

## 实现

- 正文与切句结果：32MB 内存 LRU（5 分钟）+ 64MB IndexedDB（24 小时），容量按 JSON 字符数两倍估计。相同正文在途加载合并。
- 按 API 地址、读者、docId 隔离。每次打开仍在线校验文档详情；在途切换账号或服务器中止该次加载；被删除或无权限的文档不展示旧缓存。
- 当前句优先启动，后续句子并行预取；可重试的预取失败会转入当前句的有界重试，避免一句失败就直接降级。
- 引擎探测与相同音频合成采用单飞；音频文件命中不再等待上游探测。异步原子写入，缓存写入失败不阻断已生成的音频。
- 服务端仍使用数据库同目录的 tts 文件缓存；缓存键和浏览器音频 60MB/文档约定不变。服务端音频磁盘总容量清理沿用现有策略，未在本轮新增。

## Chrome 实测

使用独立测试数据库，本机 Chrome、Vite 开发模式。5000 段中文、正文响应约 4MB；先加载阅读器分包，再计程序触发书卡至第一句可见，刷新使用完整页面重载。

| 场景 | 正文可见 | 累计正文请求 |
| --- | ---: | ---: |
| 首次打开 | 460ms | 1 |
| 再次打开，命中内存 | 132ms | 1 |
| 刷新，命中 IndexedDB | 294ms | 1 |

这是一次开发环境样本，不是生产 SLA；首次打开仍需网络下载、切句和填充缓存。刷新仍需读取本地存储和重新渲染，缓存不能消除所有前端 CPU 成本。

改动前本机辅助测量：17 段演示书首次约 355ms、重复打开 81–85ms；5000 段整本重复打开约 356–369ms。辅助测量的导航方式与最终性能用例不同，不作严格百分比对比。

- 后端测试：262 项通过。
- 前端测试：220 项通过。
- Chrome：47 项通过，0 跳过、0 失败、0 不稳定重试。
- 新增浏览器用例验证重复打开与刷新不下载正文，切换账号/删除后拒绝展示旧正文。
- 单元回归验证 LRU/TTL/失败重试、在途切换账号与服务器、当前句优先、预取失败转前台、音色探测与合成单飞、音频格式隔离和上游离线缓存命中。
- 独立代码复核复现过服务器切换污染和预取失败不重试，修复后均重新验证通过。

## 边界

本轮检查的是项目现有朗读 TTS 链路，不是麦克风语音识别。本机 Kokoro 不可用；服务端合成去重、离线命中使用可控上游单测验证，没有将测试桩耗时当作真实语音合成延迟。全新句子的首次合成仍取决于上游性能和网络。

缓存不会绕过授权。没有实现完全离线打开正文；缓存不可用时仍回退原有网络加载路径。未修改 SQLite schema，未重建实际业务数据库，未提交 Git。
