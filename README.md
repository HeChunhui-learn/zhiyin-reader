# 知音漫卷（zhiyin-reader）

软件工程课程设计 · 第一组

跨平台阅读 Web 应用：读者导入 EPUB / TXT / Markdown，系统解析为结构化数据，在浏览器里图文混排滚动阅读，并能**逐句高亮跟读**；阅读进度与书签**跨设备同步**。

**开发已全部完成**：R0–R6 六轮 + R7（阅读体验与个人化）+ 四个角色迭代分支 `V1.A` / `V1.B` / `V1.C` / `V1.D`，**460 项自动化断言全绿**。

## 怎么跑

要开**两个终端**：

```bash
# 终端 1 —— 服务端（3000）
cd zhiyin-reader/server
npm install                # 首次
npm run seed               # 首次：建库 + 灌入演示数据
npm run server

# 终端 2 —— 前端（5173）
cd zhiyin-reader/client
npm install                # 首次
npm run dev                # → http://localhost:5173
```

也可以直接双击项目根目录的 **`start.bat`**，它会自动做完上面这些。

打开 http://localhost:5173，用演示账号登录：

```
demo@example.com  /  demo12345
```

登录后就能看到书架上摆着数据库里的《人间词话》。也可以自行注册（账号填手机号或邮箱、密码至少 8 位）。

数据库文件在 `server/data/zhiyin.db`，JWT 密钥在同目录 `.jwt-secret`（首次启动自动生成）。
要重建：`cd server && npm run db:reset && npm run seed`。

> ⚠️ **改了 `server/sql/schema.sql` 的列或表之后必须重建**，`npm run seed` 不会迁移已存在的库。
> ⚠️ **Kokoro 没装也能演示** —— 会自动降级成浏览器发声，跟读全链路照常可用。

## R2 已完成（账号 + 导入）

**认证**

- 自签 HS256 JWT，访问令牌 30 分钟；刷新令牌 256 位随机串、以哈希存库、**每次刷新即轮换**
- 口令用 scrypt 加盐哈希；连续失败 5 次锁定 15 分钟
- 刷新页面后靠 localStorage 里的刷新令牌静默换新，不用重新登录

**导入**

- 点「导入文档」选一个 **TXT 或 Markdown** 文件 → 浏览器内解析 → 上传入库 → 书架出现新书
- 重复导入同一本书会被服务端按内容哈希拒绝，并给出「打开它」按钮
- EPUB 会明确提示"将在 R3 接入"

**接口形状已按《接口说明文档》契约对齐**

| 项 | 之前 | 现在 |
|---|---|---|
| 错误体 | `{code, message}` | `{code, message, details, requestId}`，响应头带 `X-Request-Id` |
| 书架列表 | `{items}` | `{total, page, pageSize, items}` |
| 字段名 | `format` / `paraCount` | `fileFormat` / `paragraphCount` |
| 正文接口 | `/paragraphs` | `/content?from=&to=`，带 ETag 与 304 |
| `progress` | 数字 | `{paraIndex, percent, updatedAt} \| null` |

可以直接试的几个点：

- 注册时账号填手机号或邮箱、密码至少 8 位；填错会给出对应的中文提示
- 连续输错 5 次密码，会提示"账号已锁定，请 N 分钟后重试"
- 退出登录后再刷新页面，不会残留登录态
- 打开不属于自己的文档（比如 `demo@example.com` 的《人间词话》），会显示"该资源不属于当前用户"
- 把服务端停掉再刷新书架，显示"无法连接到服务端…"加重试按钮

## R3 已完成（EPUB + 图文混排 + 懒加载）

**导入 EPUB**

- 点「导入文档」选一个 **EPUB** 文件 → 浏览器内用 epub.js 解析 → 正文与图片一并入库
- 书名、作者取自 EPUB 的元数据（`dc:title` / `dc:creator`）
- 章节按 spine 顺序拼接；`h1`~`h6` 转成标题段，图片转成独立的图片段

**图片是懒加载 + 懒上传的**

- 导入时图片二进制**不上传**，只写进浏览器 IndexedDB
- 阅读时图片**首次滚进视口**才去取：先查本地缓存，未命中再向服务端取
- 服务端也没有、而本地有 → 顺手补传上去（这样其他设备才看得到）
- 两边都没有 → 显示"图片不可用"占位
- 图片离开视口时撤销 object URL 释放内存，IndexedDB 副本保留
- 缓存上限：单文档 300 张或总量 200MB（先到者为准），按最近使用时间淘汰

可以直接试的点：

- 导入一个带插图的 EPUB，打开后**慢慢往下滚**——图片是在快滚到时才出现的（不是一次性全加载）
- 滚回去再看，图片立刻出现（命中本地缓存，没有网络请求）
- 换个浏览器窗口（相当于换设备）打开同一本书，图片仍能显示（这次是从服务端取的）

## R4 已完成（逐句跟读接真实 TTS）

**游标不再靠定时器**——念完一句才推进下一句，所以"高亮位置与音频严格对应"这条验收要求现在是真成立的。

**两条路径，自动选**

| 路径 | 何时用 | 说明 |
|---|---|---|
| 服务端代理 + 本地 Kokoro | Kokoro 在运行 | 音频经 `POST /api/tts/synthesize`，服务端与浏览器两级缓存 |
| 浏览器原生 `SpeechSynthesis` | Kokoro 没装 / 挂了 | 界面会显示「已降级为浏览器发声」 |

**缓存与预加载**

- 缓存键 `sha256(engine + voice + rate + text)`，服务端与客户端共用，**客户端命中时连请求都不发**
- 每次朗读会预取后面 2 句，减少句间停顿
- 音频缓存上限单文档 60MB，超出按最近使用淘汰

**可以直接试的点**

- 点「跟读」，句子逐句高亮推进，自动滚到屏幕中间
- 再点一次「暂停」，游标停住不再前进
- 跟读中点任意句子——停在那一句，出现「继续跟读」提示条
- 用「上一句 / 下一句」在暂停状态下挪动位置，再点「继续跟读」从那里接着念
- 同一句重播**不会重复合成**（第二次直接读缓存）

### 想用本地 Kokoro（可选）

装上并启动 [Kokoro-FastAPI](https://github.com/remsky/Kokoro-FastAPI)（默认 `http://127.0.0.1:8880`）即可，服务端会自动探到它并把默认引擎切过去，不用改代码。

服务端认这几个环境变量：

```
TTS_BASE_URL=http://127.0.0.1:8880/v1   # 任何 OpenAI 兼容的 /v1/audio/speech 都行
TTS_API_KEY=                            # 本地服务一般不需要
TTS_MODEL=kokoro
TTS_TIMEOUT_MS=20000
```

**没装也完全能演示**——会自动降级成浏览器发声，跟读全链路照常。

## R5 已完成（跨设备同步 + 冲突处理）

**三个必演示项到这里就齐了。**

**阅读进度**

- 每台设备一行记录，打开文档时拉取**所有设备**的进度
- 滚动停止 1500ms 后自动上报（防抖）；页面隐藏/关闭时补一次
- 恢复位置时**不回退**：如果别的设备读得更前就用它，但如果本机自己记录的位置更靠前，保留本机的
- 书架上的进度条现在是真实的

**书签**

- 阅读界面右上「书签」面板：加当前位置、跳转、重命名、删除
- 软删除（墓碑），其他设备能拉到删除事件

**冲突**

- 两端改同一条书签 → 服务端按「两份都保留」处理，**第二条记录的 id 由服务端生成**，本机那份名字带「（本机）」后缀
- 一端删、另一端改 → 保留修改，不执行删除，并标注"该设备曾删除此书签"
- 进度冲突 → 按「不回退保护」自动裁决，不打扰读者
- 顶栏「同步冲突」按钮出现红色角标，点开能看到双方差异并选择保留哪一份
- 断网时的改动进本地待同步队列，下次同步补报

**演示冲突的步骤**（两个浏览器窗口，同一账号）

1. 窗口 A 打开一本书，点「书签 → 加当前位置」
2. 窗口 B 打开同一本书，把那条书签**改个名**
3. 回到窗口 A，把那条书签改成**另一个名字**
4. 顶栏出现红色角标 → 点「同步冲突」→ 能看到双方改的名字 → 选「保留云端」→ 应用
5. 到窗口 B 刷新，两边一致

> 注意：两个窗口共享 localStorage，deviceId 是同一个。真正的跨设备演示用平板 + 笔记本各连一次局域网即可。
